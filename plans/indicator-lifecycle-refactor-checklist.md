# Indicator lifecycle refactor checklist

This source-derived checklist tracks the migration of every canonical indicator
to configuration-only construction followed by explicit series ingestion.

## Required contract

- Rust core and PyO3 constructors accept configuration only.
- Python construction is `Indicator(configuration...)`; no input series, empty
  placeholder array, or implicit initial history is accepted by `__init__`.
- `extend(series...)` ingests aligned histories; `append(scalar...)` ingests one
  chronological observation; both mutate and return the same Python instance.
- `compute`, `value`, `reset`, and `__len__` retain their existing contracts.
- `TAPipeline.indicator` receives an empty configured indicator instance, so
  graph construction never needs `[]` placeholders.
- Numerical formulas, warm-up, output ordering, state transitions, and bulk
  kernels must not change.
- A row is complete only after its Python adapter, Rust core/PyO3 constructor,
  tests, interface audit, and external-oracle verification agree.
- Correctness gates run before the explicitly authorized benchmark gate.

## Shared infrastructure and consumers

- [x] Shared Python adapter bases use configuration-only constructors
- [x] Rust core constructor audit proves configuration-only construction
- [x] PyO3 constructor audit proves configuration-only construction
- [x] `TAPipeline` examples and tests use configured empty indicators
- [x] Verification registry/interfaces/correctness use constructor then `extend`
- [x] Documentation and repository examples contain no empty-series constructors
- [x] `AGENTS.md` indicator lifecycle contract reflects the new public API
